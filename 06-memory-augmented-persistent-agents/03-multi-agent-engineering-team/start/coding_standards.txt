Coding Standards

1.  Architecture & Design Principles

1.1 Use Dependency Injection for Modular Architecture - Inject
dependencies via constructors or function parameters. - Avoid hard-coded
dependencies. - Improves testability and flexibility. - Enables easier
mocking during testing.

1.2 Prefer Composition Over Inheritance - Favor assembling behavior from
smaller components. - Avoid deep inheritance hierarchies. - Improves
maintainability and reduces coupling.

1.3 Follow SOLID Design Principles - Single Responsibility Principle -
Open/Closed Principle - Liskov Substitution Principle - Interface
Segregation Principle - Dependency Inversion Principle

1.4 Keep Functions Small and Single-Purpose - Each function should do
one thing well. - Prefer readability over cleverness. - Extract complex
logic into smaller reusable units.

2.  Code Quality & Maintainability

2.1 Use Type Hints for Readability and Safety - Always type public
interfaces. - Use strict typing when available. - Avoid using ‘any’
unless justified.

2.2 Write Descriptive Commit Messages - Use imperative mood (e.g., “Add
validation for user input”). - Explain why, not just what. - Reference
issues when applicable.

2.3 Document Public APIs and Complex Logic - Document inputs, outputs,
and side effects. - Use consistent documentation standards. - Add
comments only when logic is non-obvious.

2.4 Avoid Premature Optimization - First make it correct. - Then make it
readable. - Optimize only when measured.

3.  Reliability & Error Handling

3.1 Fail Fast and Handle Errors Explicitly - Validate assumptions
early. - Throw meaningful errors. - Avoid silent failures. - Never
swallow exceptions without logging.

3.2 Validate Input Data at Boundaries - Validate API inputs. - Sanitize
user input. - Never trust external data sources.

3.3 Avoid Shared Mutable State in Concurrent Systems - Prefer
immutability. - Use controlled state management patterns. - Avoid race
conditions. - Use synchronization mechanisms when necessary.

4.  Performance & Scalability

4.1 Use Async I/O for High-Latency Operations - Network calls - Database
access - File system operations - Avoid blocking the main thread.

5.  Testing

5.1 Write Unit Tests for Edge Cases - Test boundary conditions. - Test
error paths. - Test invalid input. - Cover concurrency edge cases where
applicable.

6.  Observability & Operations

6.1 Log Meaningful Events - Log important state transitions. - Avoid
noisy logs. - Include contextual metadata. - Never log secrets.

6.2 Secure Sensitive Data and Secrets - Never commit secrets to version
control. - Use environment variables or secret managers. - Rotate
credentials regularly. - Encrypt sensitive data at rest and in transit.

Guiding Principles - Clarity over cleverness. - Explicit over
implicit. - Measured over assumed. - Secure by default. - Maintainable
over complex.
